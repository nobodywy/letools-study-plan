# 上篇 · 认知：数据是什么，值在哪

## 一、种类总览：五类数据一张表

| 数据种类 | 有动作真值？ | 规模与成本 | 主要喂给哪个阶段 | 对模型的核心价值 |
|---|---|---|---|---|
| ① 机器人遥操作数据（真机） | ✅ 精确 | 小而贵（百元级/条） | **后训练 / 微调** | 目标任务成功率的直接监督信号 |
| ② 人类第一视角数据 | ❌ 需合成转换 | 大而便宜（万小时级） | **预训练** + 规模扩展 | 任务常识、场景多样性，把数据量做上去 |
| ③ 仿真数据 | ✅ 完美标注 | 可无限生成 | **预训练**（多样性补充） | 长尾/危险场景覆盖，免费的全模态标注；有 sim-to-real gap |
| ④ 互联网视频/图文 | ❌ | 海量、最便宜 | **VLM backbone 预训练** | 视觉语义表征、物体与物理常识（"看懂世界"） |
| ⑤ 开源数据集 | 视来源而定 | 现成 | 预训练混合料 / 评测 | 站在社区肩膀上，跨本体先验 |

一句话记忆：**①越"准"但越少，④越"多"但越"虚"；微调用准的，预训练用多的。**

## 二、逐类特点与价值

### ① 机器人遥操作数据（我们手里的 `task1_0001.bag` 就是这类）

- **是什么**：操作员通过主从臂（如 ALOHA 的 leader-follower）、VR 手柄、Joystick 或动捕设备控制**真机器人**，同步录制相机图像流 + 关节状态 + 末端/关节动作。
- **特点**：
  - ✅ 本体完全匹配（就是这台机器人自己的关节和相机），动作是真值，质量天花板
  - ❌ 贵：一条 15 秒的 episode 成本几十到几百元；采 1 小时有效数据往往要数小时
  - ❌ 量上不去，且质量取决于操作员熟练度（失败、碰撞的 episode 要剔除）
- **适用阶段**：**微调 / 后训练**。ACT、Diffusion Policy 从头训，PI0/SmolVLA 微调，全靠它做监督。
- **价值**：决定"**这台**机器人做**这个**任务"能不能学会。几百条高质量的遥操作数据，通常就足够把一个策略微调到可用——这是模仿学习的黄金标准。

### ② 人类第一视角数据（egocentric）

- **是什么**：用 GoPro / 智能眼镜记录**人手**完成任务的画面（如 Ego4D 这类数据集，以及工厂现场第一视角视频）。
- **特点**：
  - ✅ 便宜、海量、场景丰富——任何人随时随地都能采
  - ❌ 没有 action 真值，没有本体感知；人手 ≠ 机械臂（**embodiment gap**）
- **适用阶段**：**预训练**。经过 Human-to-Robot 合成转换后（见下篇「获取方法」），可以升级为可训练的动作数据。
- **价值**：把数据规模从"千小时"推到"万小时"的关键。Qwen-RobotManip 不采集任何专有数据，靠「开源机器人数据 + 人类第一视角视频 + Human-to-Robot 合成」构建了约 **38,100 小时**的预训练语料，把人类演示转换成 **15 种**机器人平台的轨迹；同时它带来丰富的任务先验（人怎么叠衣服、怎么拧瓶盖）。

### ③ 仿真数据

- **是什么**：在 Isaac Lab / MuJoCo / RoboCasa 等物理引擎+渲染器里生成，配合 domain randomization（随机光照、纹理、物体位姿）。
- **特点**：
  - ✅ 标注完美且免费：深度、分割、物体位姿想要什么有什么；量可无限
  - ❌ **sim-to-real gap**：物理近似、渲染纹理与真实世界有分布差
- **适用阶段**：**预训练**的多样性补充；导航、抓取等任务可纯仿真训练。
- **价值**：低成本覆盖真实世界难以采集的场景（危险动作、稀有物体）。我们的计划因为 WSL2 + 不装 Gazebo 砍掉了这一环，但要知道它在业界的定位——真机条件不足时它是最常见的替代品。

### ④ 互联网视频 / 图文数据

- **是什么**：第三人称的人类活动视频、图文对（用于预训练 VLM）。
- **特点**：没有动作标签、不是机器人视角，但规模无上限。
- **适用阶段**：**VLM backbone 预训练**。PI0 用 PaliGemma，SmolVLA 用 SigLIP——先让模型"看懂世界"，再学"做动作"。
- **价值**：视觉语义表征 + 物理常识的来源。这解释了 VLA 和纯 ACT 的本质区别：VLA 的 backbone 里已经装进了对物体、场景、任务语言的先验知识。

### ⑤ 开源数据集

- **代表**：Open X-Embodiment（跨 22 种机器人本体）、DROID、AgiBot World、LIBERO 系列（评测为主）、LeRobot 社区数据集。
- **价值**：预训练混合料来源；跨本体数据教会模型"通用的操作规律"（这也是"统一动作表示"要解决的问题）；LIBERO-PLUS、RoboTwin-IF/XE 等 OOD 集合用于评测篇（知乎 §4）。

## 三、数据 × 训练阶段：三段式分工

以 PI0 / Qwen-RobotManip 为代表的 VLA 训练流程：

| 阶段 | 用什么数据 | 解决什么问题 |
|---|---|---|
| **1. 预训练** | 互联网视频 + 人类数据 + 多本体机器人数据混合（flow matching 训 action expert） | 通用视觉运动先验："世界上物体怎么被操作" |
| **2. 后训练 / 微调** | 目标本体的遥操作数据（少而精，几百条/任务） | **动作空间对齐**：把通用先验对齐到这台机器人的 16 维关节和 3 个相机上 |
| **3. 评测** | held-out 任务 + OOD 数据（光照/干扰物/视角变化，如 LIBERO-PLUS） | 验证是真学会还是背数据 |

核心论点（知乎 §4）：**alignment first, then scale** —— 动作空间没对齐之前，堆再多数据也没用；这就是为什么工业界强调"80 维统一动作表示""camera-frame delta EEF"这类设计，也是为什么人类数据必须先做合成转换才能进训练。

注意：**ACT / Diffusion 这类小模型没有第 1 段**，直接从几百条遥操作数据训起——所以它们上限低但门槛也低，这正是我们先训 ACT、再上 VLA 的原因。

## 四、按模态看：一条样本里有什么（对照我们的数据集）

数据转换产出的 `~/work/data_out/lerobot`（LeRobot v3，`meta/info.json`）：

| 模态 | 数据集字段 | 我们的数据 | 作用 |
|---|---|---|---|
| 视觉 | `observation.images.*` | 3 路 RGB 视频：`head_cam_h` + `wrist_cam_l/r`（480×640，10fps） | 模型"看"——头部全局视野 + 双腕局部细节 |
| 本体感知（proprioception） | `observation.state` | 16 维 = 左臂 7 关节 + 左夹爪 + 右臂 7 关节 + 右夹爪 | 模型"感知自己"——当前肢体的空间状态 |
| 动作 | `action` | 16 维，与 state 同构（位置级关节目标） | **监督信号**——模型要预测的东西 |
| 语言指令 | `task_index` → 任务文本 | 单任务（task1） | 条件输入——"告诉模型做什么" |

**关键认知**：一个数据集的**模态完整性**决定它能喂哪个阶段的模型——

- 只有视频 → 只能训 VLM backbone（④的用法）
- 视频 + 动作 + 状态 + 语言 → 才能做策略微调（①的用法）

我们的数据集是全模态的，所以能直接进下一步的 ACT 训练。153 帧 ≈ 15 秒 @10fps，一个 episode 就是"一句指令下的一段连续操作"。

# 下篇 · 实操：数据从哪来，怎么处理

## 六、获取方法

1. **遥操作采集**（对应①）：
   - 主从臂（leader-follower）：动作映射最自然，质量最高，成本也最高
   - VR 手柄：便宜、沉浸感好，精度略逊
   - Joystick / 键盘：最便宜，但高自由度（如双臂 16 维）很难操控
   - 动捕手套：采集人手细节，常用于 retargeting 前置
2. **Human-to-Robot 合成**（对应②的升级，知乎 §1 重点）：
   检测人手 → SAM3 分割 → ProPainter 修复抹掉手 → virtual finger 合成虚拟夹爪 → 估计物体位姿 → IK 反解机械臂 base pose → 渲染成机器人视角数据（Qwen-RobotManip 靠这条流水线覆盖 15 种机器人平台）
3. **仿真生成**（对应③）：物理引擎批量生成 + domain randomization
4. **复用开源数据集**（对应⑤）：下载 + 按任务/质量过滤

## 七、处理流程（通用 pipeline，对照我们跑过的每一步）

```
采集 → 清洗 → 格式统一 → 配置对齐 → 数值化 → 训练侧增强
```

| 层 | 做什么 | 工具链版（我们做的） | 工业版（知乎 §1） |
|---|---|---|---|
| 1. 采集 | 多传感器时间戳同步、相机/手眼标定 | ✅ 赛事方完成（bag 里已同步） | 同左，规模大得多 |
| 2. 清洗 | 丢帧修复、异常 episode 剔除、**跨模态质量检查**（图像-动作-语言是否一致） | ➖ 基本没做（教程假设数据干净） | **五阶段清洗** + 自动化质检，最重的环节 |
| 3. 格式统一 | 原始格式 → 统一训练格式 | ✅ `CvtRosbag2LeRobot.py`：bag → LeRobot v3（parquet + mp4 + meta） | 内部统一格式 + ECoT 思考链标注 |
| 4. 配置对齐 | 本体/夹爪/自由度配置必须与数据匹配 | ✅ `KuavoRosbag2Lerobot.yaml`：`eef_type=rq2f85`、640×480 | 统一动作表示（80 维、camera-frame delta EEF） |
| 5. 数值化 | resize / 归一化 / fps 重采样 | ➖ 训练时 dataloader 做（训练时会看到） | quantile 统计文件（PI0 微调必需，VLA 阶段碰到） |
| 6. 训练侧增强 | 随机裁剪、颜色抖动 | ➖ 训练配置里开启 | 同左 |

**体会差距**：我们一条命令跑完的"转换"，在工业版里只是中间一环——采集和清洗才是成本大头（Qwen-RobotManip 的语料约 38,100 小时，由开源机器人数据、人类第一视角视频、合成数据三路混合）。这正是精读知乎 §1 时要建立的视角。
