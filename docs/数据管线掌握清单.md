# 数据管线掌握清单（LeTools）

> [具身数据入门](具身数据入门.md)讲「数据是什么」，本文只列**工程侧**要会什么。
>
> 目标：能独立把一条 bag 变成可训练数据集，并解释中间每一步为什么这么做。
> 验收线：**L2 能改配置**；L3 能改代码为选做。

## 一、管线主线

```
ROS bag（消息流，按 topic 存）
  → kuavo_data/CvtRosbag2Lerobot.py（转换器）
  → LeRobot v3 数据集（parquet + mp4 + meta）
  → kuavo_model/train.py 的 LeRobot dataloader
  → ACT / VLA 训练
```

管线工程师只负责到第 3 步，但必须知道第 4 步怎么消费数据。

## 二、六个必会主题

| # | 主题 | 核心问题 | 代码位置 | 掌握标准 |
|---|---|---|---|---|
| 1 | ROS bag | 为什么 bag 不能直接训练？topic / msg / header.stamp 是什么？ | `common/kuavo_dataset.py` `KuavoRosbagReader` | 能列出 bag 的 topic、频率、相机/关节/夹爪来源 |
| 2 | **时间对齐** | 477 帧 @30fps 为什么输出 153 帧？`train_hz` / `sample_drop` / `jump` 各改了什么？ | `common/chunk_process.py` `generate_sample_timestamps`、`_align_single_frame` | 手算 477→153，说清「主时间线 + 最近邻 + 夹爪前向填充」 |
| 3 | **模态与动作空间** | 为什么 state/action 都是 16 维？换 `sg100` / `which_arm` / `5w_wholebody` 后怎么变？ | `configs/data/KuavoRosbag2Lerobot.yaml`、`common/config_dataset.py`、`modality_templates/` | 能为新平台改对配置并预测输出维度 |
| 4 | **LeRobot v3 格式** | 数据集由哪些文件组成？训练读 parquet 还是 mp4？meta 各管什么？ | `~/work/data_out/lerobot/`、`configs/train/lerobot/act.yaml` | 逐字段解释 `info.json`，能正确读出 shape |
| 5 | 转换器工程 | `chunk_size` / `parallel` / `resume` / `merge` 怎么用？两遍扫描为什么防 OOM？ | `CvtRosbag2Lerobot.py` `main`、`common/parallel_cvt.py` | 选对模式，能按日志定位卡点 |
| 6 | 数据质检 | 拿到数据集，怎么判断「能训」？ | `meta/stats.json`、视频、parquet | 能写 20 行自检脚本 |

其中 **2、3、4 是重中之重**，也是排障和面试最常问的。

## 三、能力分级

| 等级 | 要求 | 对应动作 |
|---|---|---|
| L1 能讲清 | 不看代码能画管线、解释每个参数 | 读 `main()` + `chunk_process.py` |
| L2 能改配置 | 换本体/夹爪/相机/帧率/分辨率 | 副本目录跑 3 组配置并 diff 产物 |
| L3 能改代码 | 新增模态/平台，改对齐策略 | 读 `KuavoMsgProcesser`、`_align_single_frame` |

## 四、动手练习（各半天）

1. **看原始数据**：`rosbag info` + python rosbag API，统计各 topic 条数/频率，对照相机原始帧数（477 / 477 / 476）。
2. **破坏帧率**：`train_hz=20`（除不尽，走插值路径）、`sample_drop=0`，输出到新目录并解释差异。
3. **验产物**：读 `data/chunk-000/file-000.parquet` 打印 16 维曲线；`ffprobe` 核对视频时长 ≈ 153/10s。
4. **故意配错**：分别试 `which_arm=left`、`eef_type=leju_claw`、错误 resize，观察 `info.json` 和报错。
5. **交给训练**：`LeRobotDataset` 加载 `dataset[0]`，核对 shape/dtype，对照 `act.yaml` 理解 dataloader。

> 都在**新 target_dir** 里做：转换器会清空输出目录。

## 五、自测八问

1. 477 帧 @30fps，`train_hz=10`、`sample_drop=10`，为什么是 153 帧？
2. 主时间线为什么选 `head_cam_h`？某路 wrist 中途丢帧会怎样？
3. `state` 和 `action` 为什么同构？换成 delta EEF 要改哪几处？
4. `features` 里图像 `dtype=video`，训练时到底读什么？
5. `stats.json` 的 `q01/q99` 谁会用？VLA 微调为什么必须生成 quantile？
6. Phase 1 / Phase 2 各做什么？为什么能控内存？
7. modality template、`info.json features`、`config_dataset.py` 三者什么关系？
8. 给你一个陌生数据集，列出 5 条验收检查。

## 六、常见坑

- `target_dir` 会被清空，转换前确认路径。
- `resize` 先看 bag 原图尺寸，别放大。
- `main_timeline_fps` 填真实稳定帧率，不是标称值。
- `eef_type` 必须匹配 bag 里实际的 action topic（`rq2f85` 走 claw 分支）。
- `which_arm` 同时决定相机集合和 state/action 切片，不是独立开关。
- 帧率除不尽时走插值时间戳，输出帧不对应原始帧。
- 视频编码 AV1（yuv420p），用 ffmpeg / VLC 验证兼容性。
